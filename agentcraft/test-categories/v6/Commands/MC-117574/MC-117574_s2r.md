BUG_ID: MC-117574

AFFECTED_VERSION: Minecraft Java Edition 1.13.2

BUG_BEHAVIOR:
Re-running `/setblock` on a dropper with the same block state but different block entity NBT reports failure, retains the old custom name, and clears the dropper inventory instead of applying the new NBT.

PRECONDITIONS:
- Launch Minecraft Java Edition 1.13.2.
- Use a world where the player has permission to execute commands.
- The block one block east of the player at the player’s feet level must be accessible for interaction.
- The player must remain in the same block position throughout both `/setblock` commands because they use relative coordinates.
- PRACTICAL_ASSUMPTION: Use Creative mode in a new flat world to simplify access to the dropper.

SETUP:
1. Stand still in an open area.
2. Record the player’s current block position.
3. Do not walk, jump, fly, or otherwise change position until both `/setblock` commands have been executed. Camera rotation is allowed.
4. Confirm that the target position `~1 ~ ~` is one block in the positive X direction from the player at feet level.

REPRODUCTION_STEPS:
1. While stationary, open chat and execute exactly:

```mcfunction
/setblock ~1 ~ ~ dropper[facing=up]{CustomName:"\"first\"",Items:[{id:stone,Count:1b,Slot:0b}]}
```

VERIFY:
- The command succeeds.
- A dropper appears at `~1 ~ ~`.
- Aim at the dropper and use the secondary-use input once to open it.
- Verify the inventory screen title is `first`.
- Verify the first inventory slot, slot 0, contains one stone.
- Do not remove or move the stone.
- Close the dropper interface.
- Verify the player has not changed block position.

2. Execute exactly:

```mcfunction
/setblock ~1 ~ ~ dropper[facing=up]{CustomName:"\"updated\"",Items:[{id:stone,Count:1b,Slot:0b}]}
```

VERIFY:
- Observe that the command reports failure rather than success.
- Aim at the same dropper and use the secondary-use input once to open it.
- Verify the inventory screen title is still `first`, not `updated`.
- Verify slot 0 is empty. Since slot 0 was the only populated slot, the dropper inventory should now be completely empty.

EXPECTED_BEHAVIOR:
- The second command should succeed because its block entity NBT differs.
- The dropper’s custom name should become `updated`.
- Slot 0 should contain one stone.

OBSERVED_BUG_BEHAVIOR:
- The second command fails because the dropper block state is unchanged.
- The old custom name `first` remains.
- The stone is removed, leaving the dropper inventory empty.

SUCCESS_CONDITION:
Reproduction succeeds if, after the second command, all three conditions hold:
1. The command reports failure.
2. Opening the dropper shows the title `first`.
3. Dropper slot 0, previously containing one stone, is empty.
