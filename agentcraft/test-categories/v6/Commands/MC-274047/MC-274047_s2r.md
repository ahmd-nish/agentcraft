BUG_ID: MC-274047

AFFECTED_VERSION: Minecraft Java Edition 1.21  
Do not use 25w07a or later, because 25w07a is the reported fix version.

BUG_BEHAVIOR:  
Repeatedly attempting to summon a falling block whose `BlockState.Name` is the invalid resource location `"?"` writes repeated exception stack traces to the game log. Sustained exceptions can cause lag and excessive log growth.

PRECONDITIONS:

- Launch Minecraft Java Edition 1.21.
- Create or open a world with commands enabled.
- The player must have permission to use command blocks.
- The execution environment must allow inspection of the current game log, normally `logs/latest.log`.
- PRACTICAL_ASSUMPTION: Use a singleplayer Creative Mode world to simplify command-block placement and deactivation.
- PRACTICAL_ASSUMPTION: Make a backup or use a disposable world because the repeating command may cause substantial lag.

SETUP:

1. Enter the world and stand on solid ground with space to place a command block and lever.
2. Obtain a repeating command block by opening chat and running:

```mcfunction
/give @s minecraft:repeating_command_block
```

3. Obtain a lever by running:

```mcfunction
/give @s minecraft:lever
```

4. Place the repeating command block on the ground.
5. Interact with the command block to open its configuration screen.
6. Configure it as:
   - Mode: `Repeat`
   - Condition: `Unconditional`
   - Redstone: `Needs Redstone`
7. Enter the following reported command into the command field:

```mcfunction
/summon minecraft:falling_block ~ ~ ~ {BlockState:{"Name":"?"}}
```

   If the command-block field does not accept a leading slash, enter the same command with only the initial `/` omitted:

```mcfunction
summon minecraft:falling_block ~ ~ ~ {BlockState:{"Name":"?"}}
```

8. Confirm the command-block configuration and close its interface.
9. Place the lever on a face of the command block.
10. Verify the lever is off and the command block is not powered.
11. Open or record the current end position of the active game log so newly generated messages can be distinguished from older messages.

VERIFY:

- The placed block is a repeating command block.
- Its stored command contains `BlockState:{"Name":"?"}` exactly.
- It is set to `Needs Redstone`.
- No repeated exceptions are being generated while the lever is off.

REPRODUCTION_STEPS:

1. Use the lever once to switch it on and power the repeating command block.
2. Leave it powered for approximately 2 seconds. The repeating command block should attempt the summon command every game tick.
3. Use the lever again to switch it off. Do this promptly if the game begins lagging.
4. Inspect only the game-log entries generated during the powered interval.
5. Look for multiple exception stack traces associated with loading or summoning the falling-block entity and parsing the invalid resource location `"?"`.

VERIFY:

- Multiple substantially equivalent exception stack traces appear during the short interval when the command block was powered.
- The exceptions stop accumulating after the lever is switched off.
- A command failure message or failure to summon the entity is only intermediate behavior. It is not by itself proof of this bug.
- The required verification evidence is repeated stack-trace output in the game log.

EXPECTED_BEHAVIOR:

Minecraft should reject the invalid `BlockState.Name` without repeatedly writing full exception stack traces. At most, it should produce a concise error informing the player or server operator that the value is invalid.

OBSERVED_BUG_BEHAVIOR:

While the repeating command block is powered, Minecraft repeatedly writes exception stack traces to the game log because `"?"` is invalid in the resource-location field. Repetition may increase log size and cause MSPT, TPS, or general performance degradation.

SUCCESS_CONDITION:

Reproduction succeeds if at least two equivalent exception stack traces caused by the supplied falling-block command are added to the game log while the command block is powered.
