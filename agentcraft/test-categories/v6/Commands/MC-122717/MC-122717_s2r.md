BUG_ID: MC-122717

AFFECTED_VERSION: Minecraft Java Edition 1.20.6

BUG_BEHAVIOR:
When `/tag` finds multiple entities but changes only one, the command feedback reports the total selector match count instead of the actual affected count. In this reproduction, the second command changes 1 entity but reports 6 entities.

PRECONDITIONS:
- Launch Minecraft Java Edition 1.20.6.
- Create a new Creative-mode Superflat world.
- Enable commands/cheats.
- Command feedback must be visible in chat.
- Use a single player.
- Do not add other players during reproduction.

SETUP:

1. Enter the world and open chat.

2. Ensure command feedback is enabled:

```mcfunction
/gamerule sendCommandFeedback true
```

VERIFY:
The command reports that `sendCommandFeedback` is now `true`, or was already `true`.

3. Enter Creative mode:

```mcfunction
/gamemode creative
```

4. Remove every loaded non-player entity so that the selector will have exactly six entities after setup:

```mcfunction
/kill @e[type=!minecraft:player]
```

VERIFY:
No non-player entities remain loaded.

5. Create a platform at the test location:

```mcfunction
/fill -1 99 -1 6 99 1 minecraft:stone
```

6. Teleport the player onto the platform:

```mcfunction
/tp @s 0 100 0
```

7. Summon five armor stands at increasing distances from the player:

```mcfunction
/summon minecraft:armor_stand 1 100 0
```

```mcfunction
/summon minecraft:armor_stand 2 100 0
```

```mcfunction
/summon minecraft:armor_stand 3 100 0
```

```mcfunction
/summon minecraft:armor_stand 4 100 0
```

```mcfunction
/summon minecraft:armor_stand 5 100 0
```

VERIFY:
- The loaded test entities are exactly the player plus five armor stands.
- Therefore, `@e[sort=nearest,limit=6]` selects exactly six entities.
- Do not move the player before running the reproduction commands.

8. Remove the tag `test` from every test entity in case it already exists:

```mcfunction
/tag @e[sort=nearest,limit=6] remove test
```

VERIFY:
It is acceptable for this command to report that no entity had the tag.

REPRODUCTION_STEPS:

1. Add `test` to the nearest five entities using the report’s first command:

```mcfunction
/tag @e[sort=nearest,limit=5] add test
```

VERIFY:
Chat displays:

```text
Added tag 'test' to 5 entities
```

INTERMEDIATE_STATE:
- Exactly five of the six test entities now have `test`.
- Exactly one armor stand, the farthest one at `5 100 0`, does not have `test`.

2. Optionally verify that exactly one selected entity remains untagged without changing its tags:

```mcfunction
/execute as @e[sort=nearest,limit=6,tag=!test] run say UNTAGGED_ENTITY
```

VERIFY:
Exactly one entity produces an `UNTAGGED_ENTITY` chat message.

3. Run the report’s second command:

```mcfunction
/tag @e[sort=nearest,limit=6] add test
```

VERIFY:
- The selector finds six entities.
- Five already have `test` and are unaffected.
- Only the remaining armor stand receives `test`.
- Inspect the command feedback shown in chat.

EXPECTED_BEHAVIOR:
Because only one entity was changed, the second command should use the single-entity success message, equivalent to:

```text
Added tag 'test' to (some specific entity)
```

OBSERVED_BUG_BEHAVIOR:
The second command instead displays:

```text
Added tag 'test' to 6 entities
```

The displayed feedback count is the selector match count, not the actual affected count.

SUCCESS_CONDITION:
After the first command leaves exactly one entity without `test`, the second command changes only that one entity but displays `Added tag 'test' to 6 entities`.

Verification values:
- SELECTOR_MATCH_COUNT: 6
- ACTUAL_AFFECTED_COUNT: 1
- DISPLAYED_FEEDBACK_COUNT: 6
